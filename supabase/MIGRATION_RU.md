# Переезд на сервер в России (152-ФЗ)

Сейчас база — в Supabase (Ирландия), сайт — на GitHub Pages. Для **реальных пациентов** данные должны
храниться и обрабатываться на серверах в РФ. Ниже — рекомендуемый путь, при котором код сайта не меняется.

## Вариант, который рекомендую
**Supabase на своём сервере (VPS) в российском дата-центре.** Это тот же Supabase с открытым кодом:
база PostgreSQL, вход, хранилище файлов, функции. Сайт и база переносятся без переделки, меняется только адрес в `config.js`.

| Что | Где взять | Примерная цена |
|---|---|---|
| VPS: 2 vCPU, 4 ГБ RAM, 60 ГБ SSD, Ubuntu 24.04 | Selectel, Timeweb Cloud, Yandex Cloud, VK Cloud | 1 500–2 500 ₽/мес |
| Домен, например `ownlab.ru` | reg.ru, nic.ru | 200–900 ₽/год |
| Хранилище для резервных копий (S3) | Selectel / Yandex Object Storage | 50–300 ₽/мес |
| Своя почта (SMTP) | см. [SMTP.md](SMTP.md) | 0–300 ₽/мес |

Альтернатива — управляемый PostgreSQL (Yandex Cloud) — потребует писать свой сервер для входа и прав. Дольше и дороже.

## Что сделать владельцу (аккаунты и оплата — только вы)
1. Купить VPS (Ubuntu 24.04) и домен. В DNS домена создать записи **A**:
   - `api.ownlab.ru` → IP сервера (база и вход)
   - `orders.ownlab.ru` → IP сервера (сам сайт; GitHub Pages для работы с пациентами лучше не использовать)
2. Зайти на сервер по SSH в Терминале этого приложения (`ssh root@IP`, пароль от провайдера вводите сами) — дальше команды могу выполнить я.
3. Узнать пароль базы текущего проекта Supabase (задавали при создании; можно сбросить в Project Settings → Database) — он понадобится для переноса данных. Пароль вводите сами.

## Что сделаю я (по шагам)
1. **Сервер:** обновления, файрвол (открыты только 22, 80, 443), Docker, автоматические обновления безопасности.
2. **Supabase:** официальный `docker compose` из репозитория supabase, новые секретные ключи генерируются прямо на сервере
   (никуда не пересылаются), HTTPS-сертификаты Let's Encrypt через Caddy.
3. **Схема и функция:** `schema.sql` и функция `notify` (Telegram).
4. **Перенос данных:** `pg_dump` из текущего Supabase (вместе с пользователями и паролями — сотрудникам не придётся
   регистрироваться заново) → `pg_restore` на новый сервер; файлы сканов и фото — копированием хранилища.
5. **Сайт:** раздача с того же сервера по адресу `https://orders.ownlab.ru`, новый `config.js`.
6. **Резервные копии:** ежедневный `pg_dump` + копия файлов в S3-хранилище в РФ, хранение 30 дней, проверка восстановления.
7. **Проверка** всех ролей, затем переключение и отключение старого проекта.

Простой работы при переключении — 15–30 минут, лучше вечером.

## Обязательные организационные шаги по 152-ФЗ (с юристом)
- **Уведомление в Роскомнадзор** об обработке персональных данных (если ещё не подано) — с указанием места хранения (РФ).
- **Договоры с клиниками** о поручении обработки ПДн (лаборатория обрабатывает данные пациентов по поручению клиники).
- **Политика обработки ПДн** и приказ о назначении ответственного за обработку.
- **Меры защиты**, уже есть в системе: доступ по ролям (проверяет сервер), двухфакторный вход для администраторов,
  журнал действий по заказам, шифрование HTTPS. На новом сервере добавятся резервные копии и журнал входов.
- Определить **уровень защищённости** ИСПДн (специальная категория — данные о здоровье) — это решает юрист/специалист по ИБ;
  от него зависит, нужны ли сертифицированные средства защиты.

До переезда — **только вымышленные данные** в текущей системе.
